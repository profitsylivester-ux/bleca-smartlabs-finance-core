# M8 Sub-Tasks

1. **Import Pipeline Core + Upload/Mapping/Validation** — Create `import_batches`, `import_rows`, `import_mappings`, `import_errors`, `import_field_mappings` Prisma models + migration; API `POST /api/v1/imports/statement/upload` (file hash, duplicate block), `GET|POST /imports/:id/mapping` (persist field mappings per source: date format, amount convention, column indices), `POST /imports/:id/validate` (row-level validation; malformed dates/amounts → `ImportError` with original `rawData` preserved; stage gate: validation must complete before preview).

2. **Preview + Duplicate Detection + Approve/Commit/Rollback** — API `GET /imports/:id/preview` (exact committed result preview), `POST /imports/:id/detect-duplicates` (fingerprint within-file, against prior imports, against existing transactions), `POST /imports/:id/approve` (gate: no errors, duplicates resolved), `POST /imports/:id/commit` (create `Transaction` + `JournalEntry` per row; set `verificationStatus = PENDING_VERIFICATION`, `source`, `importDate`), `POST /imports/:id/rollback` (delete created rows, restore pre-import state, audit). Seven-stage gate enforced: Upload → Map → Validate → Preview → Duplicates → Approve → Import.

3. **Reconciliation Sessions + Matching Engine** — Create `reconciliation_sessions`, `matching_rules`, `reconciliation_matches`, `reconciliation_exceptions`, `reconciliation_adjustments` Prisma models + migration; CRUD `/api/v1/reconciliations` (per treasury account, period, target kind); `POST /reconciliations/:id/auto-match` (exact, date-window, amount-tolerance, reference-similarity, one-to-many, many-to-one; configurable rule ordering + confidence threshold); `POST /matches/:id/confirm` (human confirmation required; no auto-commit); exception queue for unmatched/low-confidence.

4. **Reconciliation Adjustments + Approval/Lock/Reports** — `POST /reconciliations/:id/adjustments` (create adjustment journal entry; requires reason code; balanced + linked; approval-gated before post); `POST /reconciliations/:id/approve` (gate: difference = 0, all matches confirmed, adjustments approved); `POST /reconciliations/:id/reopen` (with reason); reconciliation reports (matched, exceptions, adjustments, outstanding).

5. **UI Screens + Integration Tests** — `/treasury/statement-import` wizard (7 steps with stage gates), `/treasury/statement-import/[id]/errors` (error queue with resolve workflow), `/treasury/reconciliation` (list + filters), `/treasury/reconciliation/[id]` (workbench: proposed matches, confirm, exceptions), `/treasury/reconciliation/[id]/exceptions`, `/treasury/reconciliation/[id]/reports`. Tests: stage gates block; duplicate hash rejected; malformed data → error queue with `rawData`; preview = commit; rollback restores state; one-to-many/partial matches correct amounts; auto-match requires confirm; zero diff before approve; adjustment needs reason; posted adjustment balanced + linked.
